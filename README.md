# 项目雷达 Project Scan

把工作区里做过的每一个项目，按最近更新时间排成一面卡片墙。名称、最后更新时间、用途概要一眼可见；鼠标悬停直接运行；项目里如果还藏着可独立运行的子项目，也能一层层点进去；其他目录的工作区也可以一键加入一起扫描。


## 为什么做这个

项目越攒越多，最近在做的那个总是被埋在几十个文件夹里；有些项目的说明还不在 README 里，有些项目真正能跑的部分在子目录。项目雷达把工作区当成一个可检索的索引：谁刚更新过、它是干什么的、能不能一键启动，都在一个页面里回答。

## 功能

- **只读扫描**：只读取目录名、文件 mtime、README、其他文档与 package.json，绝不修改已有项目的代码。
- **按更新时间排序**：取项目内有效文件的最新 mtime 与 git 最后提交时间，两者取较新者；卡片显示相对时间与绝对时间。
- **子项目下钻**：一个项目目录里可能有多个可独立运行的项目（如 toolkit-app/toolkit_fetcher、demo-app/card1 到 card6、viewer/godot）。顶层卡片显示「N 个子项目」，抽屉里用同样的卡片列出子项目，点开是二级抽屉，可单独运行、停止、看日志。
- **文档发现**：说明不一定在 README。没有 README 时自动查找项目根的其他文档（CHANNELS.md、INSTRUCTIONS.md、审查报告.md 等）与 docs 目录。
- **AI 摘要**：扫描完成后用 LLM 复核用途概要、技术标签与项目短名，写入缓存，只有内容变化才重新请求；LLM 不可用时自动退回文档启发式摘要。
- **在设置里选渠道和模型**：AI 摘要默认复用本机 DSH 的默认 LLM；也可以在「设置 → AI 摘要」里先选渠道、再选模型（数据来自 DSH 配置），不单独保存 key（使用 DSH 环境变量/凭据）。
- **自动更新（默认开启）**：服务启动时后台静默检查 git 远端，有新版本且可 fast-forward 时自动拉取；后端变更会提示「需重启后生效」，前端变更提示刷新页面，纯样式更新只 toast 一次；可在「设置 → 更新」里关闭或手动检查。
- **README 归一化**：若项目没有任何 README，而 LLM 判定某份文档实质上是它的说明，就把该文档复制为 README.md（不覆盖已有文件，可用 PROJECT_SCAN_README_COPY=off 关闭），并把一级标题改写为项目短名。
- **hover 一键运行**：自动识别 npm / pnpm / yarn 脚本、start.sh、静态页面、Godot、Python、Xcode 项目；捕获 localhost 端口后直接在新标签页打开。
- **运行状态与日志**：卡片实时显示运行中或已退出，抽屉可查看最近 200 行日志并停止进程。
- **定时扫描**：每天 09:00 到 20:00 之间每 20 分钟扫描一次，窗口外自动等到次日 09:00；扫描和 AI 摘要完成后通过 SSE 实时推送，页面无需刷新。
- **多工作区**：默认扫描当前工作区，也可以在页面里把其他本地目录加入扫描（目录选择器逐级浏览或手输路径）。所有工作区的项目出现在同一面卡片墙上，可按工作区筛选；工作区配置持久化，默认工作区不可删除。
- **隐藏项目**：在「设置」里用小眼睛图标隐藏不想看的项目（可见时眼睛睁开，隐藏后眼睛闭上），项目列表用「可用 / 已隐藏 / 全部」分段控件切换查看；隐藏只影响显示，不影响扫描、AI 摘要与运行，配置持久化。
- **磁盘占用**：每个项目（含子项目）显示所在文件夹的总计磁盘占用，包含 node_modules、.venv、素材等全部内容；扫描后异步计算，不拖慢扫描。
- **运行监控（可选，默认关闭）**：开启后每秒刷新正在运行项目的 CPU、内存、网络上下行，以及系统级 GPU 占用；关闭时不启动任何采样进程，零额外开销。
- **运行中管理**：顶部「运行中 - N」按钮打开弹层，列出所有正在运行的项目，可逐个重启/停止，也可「全部停止」；卡片上明确区分运行中与未运行。

## 快速开始

要求 Node.js 22 或以上。零第三方依赖，不需要 npm install。目录名以 `dsh-project-scan` 为例。

```bash
cd dsh-project-scan
./start.sh
# 或者：node server/index.js
```

打开 http://127.0.0.1:8790 即可。服务只监听 127.0.0.1，不对外网开放。

默认工作区是当前工作区（应用目录的上一级），可以用环境变量覆盖；其他工作区在页面右上角「工作区」里添加：

```bash
PROJECT_SCAN_ROOT=/path/to/workspace PORT=8790 node server/index.js
```

手动触发一次「扫描 + AI 摘要 + README 归一化」：

```bash
node scripts/enrich.mjs --scan --report
```

## 部署到其他设备

- 打包产物在 `dist/project-scan-1.0.0.tar.gz`（另有 `.zip`），解压到任意工作区目录即可运行，零第三方依赖、无需 `npm install`。
- 目标机器只要有 Node.js 22+；macOS 功能最全，Linux 上 GPU / 网络按进程监控不可用属平台限制，界面会自动标注。
- 零第三方依赖、无需 `npm install`；默认扫描应用目录的上一级，可用 `PORT` / `PROJECT_SCAN_ROOT` 等环境变量覆盖。

## 界面怎么用

1. 顶部导航左侧（logo 旁）显示扫描状态和下次扫描时间；右侧按钮可以立即手动扫描。
2. 搜索框按名称、用途概要与标签实时过滤；排序可在「最近更新」和「名称」之间切换；标签筛选只展示最高频的十个标签。
3. 卡片右下角的「运行」按钮在悬停或键盘聚焦时出现。运行中会变成「停止」，并显示状态点。顶层项目自身不可运行但有可运行子项目时，按钮显示「子项目 N →」，点开抽屉选择。
4. 点击卡片打开右侧详情抽屉：完整摘要、路径、git 信息、文件数、体积、运行控制与日志。有子项目时抽屉里会多出一块子项目卡片。
5. 点击子项目卡片打开二级抽屉（叠在上级之上，带返回按钮），可以单独运行子项目并查看日志。ESC 先关最上层。
6. AI 摘要进行中时，概览区显示「AI 摘要生成中」，完成后显示模型名并更新卡片；卡片上的「AI 摘要」小标签表示摘要来源。
7. 右上角「工作区」打开管理弹层：可以看到默认工作区和已加入的其他工作区（含路径与项目数），默认工作区不可删除；「添加工作区」用目录选择器浏览本机目录，或直接输入绝对路径（支持 ~）。加入后会立即扫描，工作区多于一个时工具栏出现工作区筛选，卡片上会标注所属工作区。
8. 右上角齿轮图标打开「设置」，设置按功能分 4 个 tab：运行监控 / AI 摘要 / 隐藏项目 / 更新。在「隐藏项目」里点每行右侧的小眼睛图标切换：眼睛睁开表示显示，点击后眼睛闭上即隐藏，再点恢复；「项目列表」标题右侧的分段控件可以切换「可用 / 已隐藏 / 全部」，默认只看可用项目。
9. 卡片与详情里会显示项目文件夹的总计磁盘占用（含依赖与素材）；详情里同时保留原来的「体积」字段。
10. 设置弹层里可以打开「运行监控」开关（默认关闭）。开启后运行中项目的卡片上会出现每秒刷新的 CPU、内存、网络指标，详情里还有 GPU（系统）、进程数与采样时间。
11. 顶部「运行中 - N」按钮显示当前运行中的项目数（含子项目），点开弹层逐条查看运行中的项目：可单独「重启」或「停止」；底部红色「全部停止」按钮旁有「包含当前扫描器」复选框（默认不勾选），点击全部停止需要二次确认，勾选时扫描器服务也会一起停止（页面会断开）。卡片上运行中的项目使用强调边框与呼吸点，可运行但未运行的项目显示灰色「未运行」。



## 扫描规则

- 只扫描工作区的一级目录，跳过隐藏目录与明显的系统目录（node_modules、.git、dist、build、.godot、.venv、__pycache__ 等）。
- 一个目录被判定为项目，需要至少满足一项：有 README、有 .git、有 package.json / project.godot / requirements.txt / pyproject.toml / index.html / Makefile / start.sh / run.sh / CMakeLists.txt / *.xcodeproj / *.sln / build.gradle，或包含两个以上源码文件。
- 纯素材目录（没有 README、没有代码、没有项目标记）不会出现在卡片墙上。
- 子项目下钻：在每个顶层项目内相对深度 2 层以内，查找「可独立运行的项目根」——package.json 且 scripts 含 dev/start/serve/preview、project.godot、*.xcodeproj、或带伴随文档的 start.sh/run.sh、server.py/app.py/main.py。只有 index.html 的目录不算子项目；已识别为子项目的目录不再继续下钻。
- 更新时间取「有效文件最新 mtime」与「git 最后提交时间」的较新者；文件数、体积与 git 信息一并统计。
- 整轮扫描目标在 5 秒内完成，单个目录读取失败不会中断整轮扫描。

## 多工作区

- 默认工作区由 PROJECT_SCAN_ROOT 决定（默认是 应用目录的上一级），启动时始终存在，不能删除。
- 在页面里添加的其他工作区会持久化到 data/workspaces.json，最多 10 个（含默认工作区）。
- 添加时校验：必须是存在的目录、可读、同一真实路径不能重复、不能是 project-scan 自己的数据目录；支持绝对路径与 ~ 开头的家目录路径。
- 每轮扫描遍历所有工作区（默认工作区在前），单个工作区扫描失败只记录错误并保留它上一次的项目，不影响其他工作区。
- 项目 id 保持全局唯一：默认工作区的项目沿用目录名 slug，其他工作区的项目加「工作区 id --」前缀（例如 ws-design-kit--my-app）；子项目 id 会自然带上同样的前缀。
- 目录选择器只列出目录、不读文件内容、默认隐藏点开头的目录，接口只监听 127.0.0.1。



## 隐藏项目

- 顶部导航的齿轮按钮打开设置弹层，里面列出所有已扫描的顶层项目（名称、工作区、路径摘要），点击行右侧的小眼睛图标即隐藏（眼睛闭上），再点恢复（眼睛睁开），改动立即保存。
- 隐藏配置持久化在 data/hidden.json，只记录项目 id；项目被移走后记录保留但不再参与计数。
- 项目列表标题右侧的分段控件「可用 / 已隐藏 / 全部」带数量，默认「可用」；切换与搜索、排序、标签筛选、工作区筛选叠加生效。
- 隐藏只影响默认视图的展示：被隐藏的项目仍然正常扫描、生成 AI 摘要，也仍然可以运行、预览和查看详情；「全部」视图里它们会带一个「已隐藏」标记。
- 子项目不能单独隐藏，隐藏父项目即隐藏它的全部子项目。



## 磁盘占用

- 扫描完成后异步对每个项目的文件夹执行一次总计大小计算（等价 du -sk，包含 node_modules、.venv、素材等全部内容），结果写入项目数据并通过 SSE 刷新页面。
- 计算不阻塞扫描：扫描仍是亚秒级；磁盘统计在后台跑，单次约 1 秒（30 个项目并行 4 路）。
- 单个项目计算失败（权限、目录消失）只在详情里显示原因，不影响其他项目。
- 详情里同时保留两个数值：「磁盘占用」是文件夹总计，「体积」是扫描到的文件体积。


## 运行监控（可选）

- 默认关闭。在设置里打开后，后端每 1 秒对「正在运行中的项目」采样一次；关闭开关或没有运行中的项目时不会启动任何采样进程。
- 指标：项目进程树的 CPU 百分比、内存 RSS、进程数；进程树每秒网络收发字节；系统级 GPU 利用率（macOS 无法按进程统计 GPU，界面标注「系统 GPU」）。
- 采样实现：CPU/内存优先用 ps 的累计 CPU 时间与 RSS 差分；环境不允许执行 ps 时自动降级为「当前环境不支持读取进程 CPU」，不会报错。网络用 nettop 单次采样（进程累计字节）做差分，GPU 用 ioreg 读 IOAccelerator。系统 CPU 用 os.cpus() 差分。
- 采样只在有运行中项目时进行，且每秒的总开销很小；具体实测数据见下方「资源开销评估」。

### 资源开销评估（本机实测）

在 macOS arm64（8 核）上，用真实项目（movie-data，uvicorn 常驻）实测：

| 场景 | 服务端自身 CPU | 外部采样命令 | 说明 |
| --- | --- | --- | --- |
| 监控关闭 | 0 | 0 次/秒 | 不启动任何采样子进程 |
| 开启但没有运行中项目 | 0.11ms/秒 | 0 次/秒 | 每秒只做一次空检查 |
| 开启且有 1 个运行项目 | 3.8ms/秒（0.38% 单核） | 约 2.6 次/秒、CPU 约 23ms/秒 | 合计约 2.7% 单核，即 8 核整机约 0.34% |
| 关闭后 5 秒 | 0ms | 0 次 | ticks 不再增长，无残留 nettop |

- 外部采样命令的单次 CPU：nettop 约 14ms，ioreg 约 12ms（每 2 秒一次），pgrep 约 3ms，vm_stat 可忽略；CPU 本身按 1 秒一次 ps 采样时（需要系统允许执行 ps，本机 DSH 沙箱禁止，会降级显示「不支持」），预计额外 2~4% 单核，合计约 5~6% 单核。
- GPU 只能是系统级利用率（macOS 无法按进程统计 GPU），ioreg 每 2 秒一次，约 0.6% 单核。
- 磁盘占用统计：du 并发 4，默认工作区 30 个项目约 0.9 秒 wall / 1.6 秒 CPU，每 20 分钟一次，均摊 <0.15% 单核；加入 24.6GB 级目录时单目录 du 约 4.2 秒，全量约 7.6 秒（后台异步，不阻塞扫描与页面）。
- 结论：功能默认关闭时几乎零开销；开启且正好有项目运行时，约占用单核 3%（沙箱环境）/ 6%（ps 可用环境）的 CPU，折合 8 核整机不到 1%；磁盘统计均摊可忽略。


## 运行中的项目

- 顶部「运行中 - N」按钮实时显示运行中的项目数量（顶层项目与子项目都算，**扫描器服务自身也算一条**，因此服务在线时 N 至少为 1）。
- 打开弹层后每 2 秒刷新一次：每条包含项目名、所属工作区、子项目的父路径、启动时长、状态与访问地址；「停止」会杀掉进程并从列表移除，「重启」只重启这一条（停止后重新启动）。
- 列表固定包含扫描器自身（标注「扫描器」与「外部启动」）：它由外部 start.sh 启动，不能单条重启/停止；只有勾选底部「包含当前扫描器」再点全部停止才会关闭它。扫描器项目的卡片同样显示「运行中」（合成运行状态）与「扫描器运行中」标记，不提供单条停止按钮。
- 底部「全部停止」会停止所有运行中的项目并等待退出；旁边的「包含当前扫描器」默认不勾选，勾选后会把扫描器服务本身也关掉（页面会断开，需要手动重新启动服务），因此点击全部停止必须二次确认。
- 卡片状态：运行中的项目有强调边框与呼吸点，可运行但未运行的项目显示灰色「未运行」，不可运行项目仍显示分类文案。


## 文档发现与 AI 摘要

- 文档优先级：README.md / readme.md / README.txt 等；没有 README 时取项目根的其他 md 文档（按文件名相关度排序）与 docs 目录下的 md 文件，最多 3 份、每份读取前 64KB。
- 扫描阶段先用文档做启发式摘要，保证扫描本身足够快（不到 1 秒）。
- 扫描完成后异步调用 LLM 生成：项目用途概要（40 到 120 字）、技术标签（最多 4 个）、项目短名，以及「哪份文档实质上是 README」。
- 默认直接复用本机 DSH 里已经配置好的默认 LLM（读取 DSH profile 的 `agent-default-model` 与 `llm-pi-ai` 渠道配置及 `~/.dsh/.credentials.yaml` 里的 key，走 OpenAI 兼容接口）；不需要在项目里再配置一份 key。读不到 DSH 时回退到 `DEEPSEEK_API_KEY` / `PROJECT_SCAN_LLM_*`，都不可用时退回文档启发式摘要。
- 也可以在「设置 → AI 摘要渠道」先选渠道、再选模型（渠道与模型列表来自 DSH 配置；只保存 provider/model，不缓存 token，key 仍从 DSH 环境变量/凭据解析）。保存后立即按新模型重算摘要。
- 结果按项目内容指纹缓存在 data/llm-cache.json，只有文件变化才重新请求；首次全量约 40 到 60 秒，之后通常几秒内完成。
- README 归一化：仅当项目完全没有 README 时才复制，绝不覆盖已有 README；复制记录写入 data/readme-copies.log，复制后的 README 一级标题会被改写为项目短名，保证卡片名稳定。
- LLM 不可用（没有 key、网络失败、PROJECT_SCAN_LLM=off）时，摘要退回文档启发式或兜底文案，页面其他功能完全不受影响。

## 运行规则

按以下顺序识别运行入口：

1. package.json 的 scripts：dev > start > serve > preview（根据 pnpm-lock.yaml / yarn.lock / package-lock.json 选择包管理器）。
2. start.sh 或 run.sh。
3. index.html：走静态预览，地址为 /preview/项目id/。
4. project.godot：调用 Godot 打开项目。
5. server.py / app.py / main.py：用 python3 启动。
6. *.xcodeproj：调用 Xcode 打开。
7. 都没有时按钮禁用，并提示「没有找到可识别的运行入口」。

启动后的 20 秒内会从输出里捕获地址，统一写成 http://127.0.0.1:端口，捕获到就直接打开。项目自带 .venv 时会优先使用虚拟环境（start.sh 里的 pip / python3 指向 .venv，解决系统 Python 缺依赖或 pip 无写权限的问题）。如果 20 秒内输出里没有地址，会读取 README、start.sh 等文档里写明的本机端口并探测是否已在监听；仍未拿到则提示已启动但未捕获地址，并在后台继续等待输出 120 秒，地址出现后会通过 SSE 补上。每个项目同时只允许一个运行实例；停止时先 SIGTERM，3 秒后 SIGKILL 整个进程组。子项目用同样的规则运行，运行状态按子项目 id 独立管理。

## 安全边界

- 只读扫描，不写入已有项目的代码；应用数据只落在 project-scan/data。
- 唯一的写操作是 README 归一化：仅当项目没有任何 README 时，把判定为说明文档的文件复制为 README.md，绝不覆盖已有文件，可用 PROJECT_SCAN_README_COPY=off 关闭。
- 服务只监听 127.0.0.1；目录选择器只列目录名、不读文件内容，工作区路径必须显式添加。
- 静态预览做了路径穿越防护，只能访问项目目录内的文件。
- 运行命令来自项目自身的 scripts 或约定入口文件，不做任意命令注入。
- 服务退出时会清理所有由它启动的子进程。

## 已知限制

- 不打印访问地址的运行命令最多等 20 秒才返回（期间前端显示「启动中…」）；端口捕获是启发式，错误日志里出现 127.0.0.1:PORT 可能被误判。
- 子项目识别基于「强运行入口」启发式，纯 index.html 的静态目录不会单独成卡片；如需强制收录可在 config.json 里调整。
- AI 摘要需要网络与 API key；首次全量较慢，之后走缓存。
- 项目雷达自己也在工作区里，会作为一张卡片出现。

## 技术栈

Node.js 原生 http / fs / child_process / fetch，零第三方依赖；前端为原生 HTML、CSS、JavaScript，无构建步骤；字体使用 Geist 与 Geist Mono；AI 摘要使用 OpenAI 兼容接口。
